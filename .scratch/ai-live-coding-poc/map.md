# Map: AI-native live-coding POC

Label: `wayfinder:map`

## Destination

A **buildable POC spec** for a browser live-coding environment where the human codes music in Strudel **and visuals in Hydra**, and one AI pair-programmer agent inspects and modifies both through a small, controlled tool set. The map closes when every decision below is locked and written up tightly enough to hand to a normal build cycle. **No POC code is produced on the map** — prototypes raised on tickets are throwaway.

The POC exists to judge whether the long-term vision (semi-autonomous AI performers in an audiovisual jam) is worth pursuing. That judgment is a later effort, not this map.

## Notes

- **Domain**: browser live-coding / algorithmic music. Strudel (TidalCycles in JS) is the music surface.
- **Skills every session should consult**: `/grilling` and `/domain-modeling` by default; `/research` for AFK research tickets; `/prototype` for prototype tickets.
- **Audio and visuals (destination redrawn 2026-09-29, after 09).** Hydra came into scope with the agent **co-driving** visuals, not only the human performing them. Closed decisions 01–09 assumed audio only; each still holds unless a later ticket amends it. The Surface (03) was the door left open for this.
- **Four acceptance scenarios** the spec must satisfy. Every ticket is judged against all four:
  1. *Vary what I have* — a pattern is playing; "make the hats busier and swing it" modifies existing code in place without stopping audio.
  2. *Add a part* — "add a bassline that fits" writes a new voice alongside the human's.
  3. *Get me unstuck* — "make this more like dub techno" reaches for Strudel functions the human doesn't know.
  4. *Give me visuals for this* — the agent writes a new Hydra Part that fits the music and follows it (e.g. pulses with the kick): writing Hydra *and* linking it to an audio Part. Scenarios 1–3 apply to visual Parts too ("make it glitchier" is *vary what I have*).
- **Deliberately small.** Reject speculative infrastructure unless one of the four scenarios requires it.
- **Stack reconsidered during 07 and kept: web + Strudel.** The agent's tools run in the same page as the runtime, and the long-term vision (Hydra, generative UI) is web. Native Tidal would buy sound quality, which Strudel's OSC→SuperDirt output may recover later without a rebuild. No agent framework (LangChain, MS Agent Framework).
- **Learning goal: Effect**, confined to the runtime core (agent loop, `change_parts` pipeline, dry-run). Strudel is wrapped at the edges; the UI stays plain.
- **Long-term context (do not expand scope into it)**: multiple semi-autonomous agents, agent-to-agent reaction, generative UI, agent-to-UI protocols, bounded autonomous initiative, audiovisual performance. Preserved so obvious architectural dead ends get avoided — never so tickets grow.

## Decisions so far

<!-- one line per closed ticket: gist + link -->

- [10 — Latency & control budget](issues/10-latency-and-control-budget.md): **the pass/fail line isn't agent speed, it's not disturbing the Performance.**
  - **Turn limits:** landed within 30 s for 9 in 10 Instructions, a timeout at 60 s, and at most 3 retries. Time is measured in seconds, with the Apply's cycle wait reported separately. No target for the first streamed character.
  - **No-freeze rule:** never an audible glitch. No agent job holds the main thread over 50 ms, and zero late notes during a Turn. No fix is built in advance; a worker is the noted remedy.
  - **Visuals:** ≤ 1 dropped frame (limit 100 ms) on Apply, and flashes within ±40 ms of the audible onset, on a real laptop GPU.
  - **Esc:** stop-to-quiet ≤ 200 ms.
  - **Model:** Opus 5.5 at `medium` for every scenario, with Sonnet 5.5 as the fallback, and a 1-hour cache on the fixed prefix.
  - The spec must record a timing record per Turn, long tasks and late notes, frame times and a sync estimate, downloadable as JSON from Ctrl-J.
- [16 — Visual Parts in the Performance](issues/16-visual-parts.md): **a visual Part is ``label: hydra`…` ``, and it follows the music only through four helpers**: `cycle()`, `pulse('part')`, `value('part','ctl')` and `level('part')`. `level` needs `.analyze('<part>')` on the audio Part. No `H` and no `a.fft`, and the link is only code. The Surface is derived from the tag. Everything else is the audio rule on a second Surface:
  - the host resets outputs before every evaluate, so out-of-Scope visuals keep showing and deleted ones linger until a full Apply;
  - there is no separate quantisation;
  - muted visuals aren't drawn, and solo works within a Surface;
  - errors while playing are attributed to their Part and reported once, with no auto-revert.
  The dry-run gains a hydra-synth step with probes and new `invalid` kinds. It warns on hidden outputs, missing `.out()` and broken links. Last `.out()` wins. `hydra-synth@1.4.0` is pinned with our own glue. Highlighting only, no completion. Amends ADRs [0001](../../docs/adr/0001-source-is-truth-parts-are-a-projection.md), [0002](../../docs/adr/0002-scoped-composition-on-published-strudel.md) and [0004](../../docs/adr/0004-one-tool-state-pushed-dry-run-gated.md); new term **Visual Part**.
- [15 — Hydra knowledge grounding](issues/15-hydra-knowledge-grounding.md): **the model's Hydra is already good**: 47/47 names real, 10/10 chains render, 48/52 registry functions recalled. Grounding is ~970 cached tokens, with no tool or retrieval: a signature index generated from hydra-synth's `glsl-functions.js` (~580) plus a "Hydra inside Strudel" note (~390). With 06 that is ~12.2K tokens. The gaps are all Strudel embedding traps: quoted args become Patterns, globals clash, `a` is undefined or the microphone. 14's glue (``hydra`…` `` bodies untranspiled, `makeGlobal:false`) dissolves most of them, so the note shrinks once 16 fixes the Part shape. [Full research](research/15-hydra-knowledge-grounding.md).
- [14 — Hydra inside published Strudel](issues/14-hydra-in-published-strudel.md): **it fits, but through our own glue.**
  - Don't ship `@strudel/hydra@1.2.6`. It fetches unpinned hydra-synth from unpkg, loads a second Strudel core (which breaks `H()`), and its globals clobber Strudel's.
  - Instead, import `hydra-synth@1.4.0` pinned exactly and rebuild `H` on `@strudel/web`'s core.
  - A visual Part is ``viz: hydra`…` ``, a tagged template that returns silence with Hydra's names scoped to it. A bare `viz: osc().out()` half-applies.
  - Swaps land on the next frame, unquantised and seamless. Outputs a new Source no longer writes keep rendering, so the host resets them before each evaluate.
  - Most Hydra errors never reach `evalError`. A throwaway hydra-synth dry-run catches them in ~1.3 ms per Part.
  - Audio-reactivity goes through Strudel's `.analyze`/`getAnalyzerData` or `H()`, never `a.fft` (that is the microphone).
  - [Full research](research/14-hydra-in-published-strudel.md).
- [09 — Instruction & agent-state UX](issues/09-instruction-and-agent-state-ux.md): **ask at the cursor, watch the agent work in the code, and read everything else from one status line.** Ctrl-K opens an input at the cursor, aimed at the Part there; Tab switches to `@all`. The aim is a hint, never a restriction. The tool input streams into the editor under its Part. The Proposal is an inline diff, keys first (Alt-A/P/R). Agent text stays tinted until the human edits that Part, and a deleted Part that still sounds stays visible as a ghost. One status line carries Autonomy, the Turn's state, a retry count, warnings, a waiting Apply and errors. Esc stops the Turn. **No conversation**: a human-only peek (Ctrl-J) lists this session's Turns and opens itself on an answer. [ADR 0007](../../docs/adr/0007-instructions-at-the-cursor-state-in-one-status-line.md); prototype on branch `prototype/09-instruction-ux`.
- [08 — Frontend stack](issues/08-frontend-stack.md): **Svelte 5 + raw CodeMirror 6 on Vite, with Effect behind a plain façade.** The CM document *is* the Source, reached by the core only through an `Editor` service. The façade owns the runtime and the Turn fiber, and publishes one immutable view model into `$state.raw`. Effect 3.22 is pinned under v4-migration rules. The toolchain is pnpm exact pins, TS 7 + `@effect/tsgo` (TS 6 kept for svelte-check and typescript-eslint), ESLint, Prettier, Vitest, Tailwind v4 and Bits UI. *Amended:* tests run in Node by default, with Vitest browser mode (Playwright) only for the real Strudel/Hydra bundle, and no component or end-to-end tests. React lost narrowly and Angular was rejected. Hydra will be a canvas layer behind a transparent editor. [ADR 0006](../../docs/adr/0006-svelte-codemirror-behind-an-effect-facade.md).
- [07 — Agent runtime & trust boundary](issues/07-agent-runtime-trust-boundary.md): **for the POC, the loop runs in the browser, in Effect, behind our own `Model` service.** This covers the POC only; tools and libraries are to be reconsidered later. The key is exposed but capped: `.env.local`, spend-limited, localhost only, never deployed. The one implementation wraps `@anthropic-ai/sdk`; `@effect/ai`, Tool Runner and agent frameworks were rejected. Failover is a swap point: Bedrock Mantle is a new configuration of the same implementation, and nothing switches automatically. A Turn ends on the first `ok: true`. A new Instruction interrupts the running Turn. Agent code runs in the page, accepted as known debt. [ADR 0005](../../docs/adr/0005-poc-agent-loop-runs-in-the-browser.md); new terms **Instruction** and **Turn**.
- [13 — Model provider seam: `@effect/ai` vs a wrapped SDK, and failover](issues/13-model-provider-seam.md) — **Effect AI covers almost everything but not per-tool `eager_input_streaming`**, which only an untested beta-header workaround reaches. It is 0.x, with 18 breaking releases in about 13 months. Hand-wrapping `@anthropic-ai/sdk` reaches every feature. **Cheapest failover is the same Claude model on Bedrock's Mantle endpoint:** the same body, only the base URL, model id and key change, and it is reachable from the browser (auth still to test). A different model family costs the wire format and, on Gemini, the live preview. [Full research](research/13-model-provider-seam.md).
- [05 — The tool surface](issues/05-tool-surface.md): **one tool, state pushed, every change dry-run.**
  - **The tool:** `change_parts({changes:[{part, rev, text}]})` replaces whole Parts.
    - `rev` is a content hash of the text read (new term **Rev**).
    - `rev: null` appends a new Part.
    - No deletion or rename. The agent can mute or solo through the label prefix.
  - **No read, evaluate, transport or `queryArc` tool.** A snapshot comes with every instruction:
    Source, Part index, the Live code of Parts with Unapplied edits, transport, error slot.
  - **Returns** `landed: proposed|written|applied` (with `warnings`) or an atomic refusal:
    `stale` (fresh text), `unapplied`, `invalid`, `bad_request`.
  - **At most one landed change per instruction** (to be discussed again).
  - **Dry-run:** evaluates the Apply's own composition over cycles 0–8. `hush()` is refused and
    control synonyms are warned.
  - **Playback errors** reach the agent only through the next snapshot.
  - **Limits:** the agent can't start or stop the transport; it may `setcps`.
  - Recorded in [ADR 0004](../../docs/adr/0004-one-tool-state-pushed-dry-run-gated.md).
- [04 — Apply semantics: how agent changes land without stealing the instrument](issues/04-apply-semantics.md): **a switch, not a single shape.** The human sets the agent's **Autonomy**: **Propose** (default; a diff with Accept / Accept & play / Reject), **Write** (lands as Unapplied edits) or **Apply** (lands and plays, quantised to the next cycle; human Applies stay immediate). The agent's request is the same at every level. One rule underneath: **the agent never touches text the human hasn't applied.** A request is refused atomically if any Part it changes has been edited since the agent read it or holds Unapplied edits, and a Proposal that fails this at accept time is **Stale**. So **Scope is derived** (the Parts touched) and never shown. The cursor needs no design. Undo is the editor's single text-only history for the POC. **Locked** 12's "no Live code contributes nothing". **Amended 12**: a deleted Part keeps sounding until an Apply of every Part. **Every agent request is dry-run first**, at every Autonomy. This was shown feasible on published 1.2.6 via a stubbed transpiler sandbox plus strict `query`, but it is blind to playback-time errors, and its spec is 05's. Ctrl-Enter is the only human gesture. [ADR 0003](../../docs/adr/0003-agent-changes-land-by-autonomy-never-on-unapplied-text.md); prototype on branch `prototype/04-apply-semantics`.
- [12 — Which Strudel build the POC targets](issues/12-strudel-build-target.md) — not the risk trade-off it looked like: **every argument for `main` dissolved**. An **Apply** never evaluates the Source; it evaluates a transient composition of every Part's **Live code** with only the in-**Scope** Parts substituted by their current text — so an agent edit is never hostage to the human's half-typed code, on *any* build. Widest Scope ≡ the Source, so "evaluate everything" is one mechanism parameterised, not two paths. That removes the need for `evaluateBlock` (and its anonymous-`$:` rejection and `allTransforms` reset), and makes **Part removal doubt-free**. So: **published npm, `@strudel/web@1.3.0` sole direct dependency** (exact-pins its own tree), **bundled with lockfile-exact pins, not a CDN import map** (`process.env.NODE_ENV` survives into `@strudel/core@1.2.6` and makes `errorLogger` throw inside a catch). **Zero patches, zero vendoring.** npm confirmed unmoved since January; gap to `main` now ~8 months. New bundle facts: sample *buffers* are memoised per URL forever, but `samples()` **re-fetches its map JSON every call**, and `hush()` clears `all(...)` — so the Preamble is always included (cost handed to 10). Anonymous `$:` is **unaddressable, not invalid**. New vocabulary **Apply** and **Scope** in [`CONTEXT.md`](../../CONTEXT.md); [ADR 0002](../../docs/adr/0002-scoped-composition-on-published-strudel.md). Which package manager/bundler is **08**'s; whether a never-applied Part is silently omitted is held **provisionally** for **04** to feel.
- [06 — Strudel knowledge grounding](issues/06-strudel-knowledge-grounding.md) — the model's Strudel is already good (**59/61 symbols callable, 8/10 statements evaluated clean** against the real bundle); no Haskell-isms, and Tidal carry-over is **function-level, not syntax-level** (`sidechain` for `duck`/`duckorbit`, `whenmod`). So grounding is a **prompt problem, not an infrastructure problem**: ship a generated, **runtime-filtered** signature+description index (~10K tokens, ~11.2K with `strudel-vs-tidal` and a do-not-use list), static and prompt-cacheable — not a cheatsheet, not a lookup tool, not retrieval. The filter is non-negotiable: **16% of documented names aren't callable in npm 1.3.0**, so it is computed against whichever build **12** picks. Source metadata (`doc.json`) is generated by the repo's own script, unpublished, with unreliable `@param` data. Hands **05** one field, not a tool: the apply tool returns `{ok, activeCode | error}` **synchronously**. [Full research](research/06-strudel-knowledge-grounding.md).
- [03 — What counts as "performance state"?](issues/03-performance-state.md) — the noun is the **Performance**: its **Source** is truth, **Parts** are *parsed* from top-level labels as a projection (never a partition — the agent sees the verbatim Source *and* the Part index), unlabelled top-level code is the **Preamble**. Per-Part buffer vs **Live code** with derived **unapplied edits**; transport is `started` + cps only (**cycle position is host machinery, not perceived**); **code only — no `queryArc`, event stream or FFT**, those return as tools in 05 if at all; mute/solo derived from the label prefix, never stored; one Performance-level error slot carrying message + phase (eval vs playback); comments are plain text, with leading comment runs attaching to the following Part. Surface-neutrality is one tag plus naming discipline, no adapters. Vocabulary in [`CONTEXT.md`](../../CONTEXT.md); [ADR 0001](../../docs/adr/0001-source-is-truth-parts-are-a-projection.md) records Source-is-truth.
- [02 — Anthropic agent-loop options for a browser-facing tool user](issues/02-anthropic-agent-loop-options.md) — Agent SDK is Node-only/out-of-process (no browser build); Tool Runner and the manual loop are the same client and run in-browser via `dangerouslyAllowBrowser` (API does serve CORS); a server-side loop needs a *blocking* transport (WebSocket) unless it's the manual loop, which can suspend across the boundary, or the Vercel AI SDK, whose client-forwarded tools do it over plain HTTP. Partial tool input is GA (`eager_input_streaming`) but unvalidated. Haiku 4.5 supports neither `effort` nor adaptive thinking. No published latency numbers exist anywhere. [Full research](research/02-anthropic-agent-loop-options.md).
- [01 — Strudel's programmatic surface](issues/01-strudel-programmatic-surface.md) — embed via `@strudel/web` (`initStrudel()` returns the whole `repl` control surface, without CodeMirror's global side effects); the buffer-vs-evaluated split is native (`state.code` / `state.activeCode`); hot-swap never drops audio and never resets the cycle clock, but is **never quantised and has no knob** — quantised apply is ours to build on `scheduler.now()`, no fork needed; **per-part addressing is the risky bit** (published npm is one blob; `evaluateBlock` is unreleased, untested and rejects anonymous `$:`) → ticket 12; playback-time errors are **invisible** to `repl.state` (`schedulerError` is dead code), so an error wrapper is day-one work; slot attribution runs through `hap.context.locations` char offsets, since the per-slot `id` reaches nothing. Canonical repo has **moved to codeberg.org/uzu/strudel**; npm is ~7 months behind `main`. [Full research](research/01-strudel-programmatic-surface.md).

## Not yet specified

- **Musical context across a session** — what the agent remembers between instructions, and whether "context" is just conversation history or something structured about the performance so far. *03 narrowed this:* the Performance is a pure snapshot of now — it holds no history, and nothing the agent did last turn is recoverable from it. So whatever memory exists is a separate thing from perceived state. *05 settled the perceived half:* a fresh snapshot is pushed with every instruction, and the agent has no read tool, so memory is purely whatever the conversation history carries. *From 02:* if the loop resends a growing transcript each turn, prompt caching is the cost lever, and it is invalidated by changing `effort`, switching models mid-session, or adding/removing tools — so this question is entangled with 05 and 10. *From 04:* an open **Proposal** is state held outside the Source, so whether the agent perceives its own pending, Stale or rejected Proposals is part of the same question. *From 09:* the human gets a session log (the peek), but it is human-only; the user wants conversation history as agent context *after* the POC, to make the agent more independent.
- **More than one landed change per instruction**: *from 05:* the first `ok` ends the agent's tool use for that instruction, because at Propose a second change silently replaces the Proposal. Accepted for now and **to be discussed again** once the POC shows whether agents want to chain. 09 found nothing that needs it: the inline Proposal shows one change.
- **How the built POC gets judged** — "fast and controlled enough" is now defined by [10](issues/10-latency-and-control-budget.md). What remains is "beautiful and enjoyable", a creative judgment that belongs to the effort *after* this map.

## Out of scope

- **Perceiving sound** — the agent reasons about code, never about audio analysis, the trigger event stream or queried pattern events ([03](issues/03-performance-state.md)). Out of *perception* permanently; [05](issues/05-tool-surface.md) kept `queryArc` out as a tool too, deferred rather than rejected.
- **Perceiving visuals** — likewise, the agent reads Hydra code and never looks at the canvas (ruled at the 2026-09-29 redraw).
- **Visual setup beyond one canvas** — Hydra's four outputs at most: no multi-screen, video input or external sources (ruled at the redraw).

- **Multiple agents** — exactly one agent; no agent-to-agent reaction or coordination.
- **Autonomous initiative** — the agent acts only when instructed. No unprompted changes, no reacting to the music on its own.
- **Persistence & sharing** — no accounts, saving, multiplayer, recording, or export. Refresh loses everything.
- **Strudel's AGPL-3.0 licensing** — the project's docs assert the licence reaches derivative UIs and even clean-room clones informed by reading the source ([01](issues/01-strudel-programmatic-surface.md)). A product-level decision about *shipping*, and the POC is a throwaway internal judgment tool, so it belongs to the later effort — but it must be settled before anything built on Strudel is released.
- **Undo and revert beyond the editor's own history, Apply-Part-at-cursor, and more than one open Proposal**: deferred by [04](issues/04-apply-semantics.md) to the version after the POC. The POC uses one text-only editor history, Ctrl-Enter only, and one Proposal at a time. The open point to carry forward is whether an agent's own write deserves a revert of text *and* sound, while an accepted Proposal "feels like code I wrote", and so whether undo depends on Autonomy.

- **Deferred past the POC by [07](issues/07-agent-runtime-trust-boundary.md)** (see [ADR 0005](../../docs/adr/0005-poc-agent-loop-runs-in-the-browser.md)):
  - A closing reply from the agent after its change lands.
  - Queueing or other handling of concurrent Instructions beyond replace.
  - A second model provider and any switch between providers. Automatic failover is ruled out entirely.
  - **Sandboxing the dry-run and moving the key off the page.** This one is debt, not a rejection: it must happen before any untrusted input (another agent's output, shared Performances, autonomous initiative) reaches the agent.

## 0. Yes — Strudel ships machine-readable function metadata

This was the cheapest thing to check and it changes the economics of every remedy.

`doc.json` is a **JSDoc-derived JSON** built by the repo's own script and consumed by both the docs site and the editor's autocomplete:

- `package.json` **[main]**: `"jsdoc-json": "jsdoc packages/ --template ./node_modules/jsdoc-json --destination doc.json -c jsdoc/jsdoc.config.json"`, wired as `pretest`/`prebuild`/`prestart`. ([`package.json`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/package.json))
- `website/src/docs/JsDoc.jsx`: `import jsdoc from '../../../doc.json'; // doc.json is built with 'npm run jsdoc-json'` — every `<JsDoc name="..."/>` on strudel.cc renders out of it. ([`website/src/docs/JsDoc.jsx`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/website/src/docs/JsDoc.jsx))
- `packages/codemirror/autocomplete.mjs`: `import jsdoc from '../../doc.json';` — the editor's completion list and hover cards are the *same* dataset. ([`packages/codemirror/autocomplete.mjs`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/packages/codemirror/autocomplete.mjs))

**It is not committed and not published.** There is no `doc.json` in the repo tree, and `https://strudel.cc/doc.json` and `/jsdoc.json` both return `404` (verified). It is a build artifact. Reproducing it costs `npm i jsdoc jsdoc-json` plus one command (done here, ~20 s).

Shape per entry: `longname`, `name`, `kind`, `description` (HTML), `params[] {name, type.names[], description}`, `examples[]` (runnable Strudel), `synonyms_text`, `tags`. Generated size: **880,961 chars / 603 entries**, of which **582 pass the same validity filter autocomplete uses** (`label && !label.startsWith('_') && kind !== 'package'`) — **545 unique names**, 385 with runnable examples, 146 with synonyms.

There is also a committed `undocumented.json` (root, **[main]**) listing **504 exported symbols across 94 files that have no JSDoc at all** — i.e. the documented reference covers roughly half the callable surface. ([`undocumented.json`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/undocumented.json), generated by [`jsdoc/undocumented.mjs`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/jsdoc/undocumented.mjs))

### The real callable surface **[npm 1.3.0]**

Enumerated by importing the published bundle in Node:

- **1017 named exports** from `@strudel/web@1.3.0` (independently reproduces the figure in 01).
- **1169 own properties on `Pattern.prototype`** — because Strudel's `register()` installs a method as well as a free function.
- **Union: 1471 callable names.**

This matters: several names are methods but *not* module exports. `layer`, `density`, `duckorbit` and `into` are all `typeof === 'function'` on `Pattern.prototype` while absent from the export list. **An export list alone is an incomplete reference; the union is the truth.**

## 1. Baseline — how good is the model's unaided Strudel?

### Method

Ten `$:` statements were written from model knowledge **before any reference was consulted**, covering the three acceptance scenarios. They were then checked two ways:

1. **Symbol check** — every method call and every bare function/signal identifier, against the 1471-name callable union and against `doc.json`.
2. **Execution check** — each statement transpiled with `@strudel/transpiler` (from the published `@strudel/web@1.3.0` bundle, after `evalScope(module)` and `miniAllStrings()`), evaluated, then `pattern.queryArc(0, 4)` to force actual hap generation. Audio output stubbed out; everything upstream of `superdough` is real.

The snippets (verbatim, as written):

```js
// S1a — "make the hats busier and swing it"
$: s("bd*2, ~ cp").bank("RolandTR909")
$: s("hh*8").gain(0.7).swingBy(1/3, 8)

// S1b
$: s("hh*16").gain(sine.range(0.4, 0.9)).sometimesBy(0.3, x => x.speed(2)).swing(4)

// S1c
$: s("hh").euclid(11, 16).ply("<1 2>").degradeBy(0.2).pan(rand)

// S2 — "add a bassline that fits"
$: note("c2 [~ c2] eb2 g1").slow(2).sound("sawtooth").cutoff(400)
     .lpf(sine.range(200, 800).slow(4)).lpq(8)
     .attack(0.01).decay(0.2).sustain(0.3).release(0.2).gain(0.8)

// S2b
$: n("0 [~ 0] 2 4").scale("c2:minor").s("sawtooth").legato(0.6).clip(0.8).orbit(2)

// S3 — "make this more like dub techno"
$: note("<c3 eb3 g3 bb3>").struct("~ x ~ x").s("sawtooth")
     .lpf(perlin.range(300, 1200).slow(8))
     .room(0.8).roomsize(6).size(6)
     .delay(0.6).delaytime(0.375).delayfeedback(0.7)
     .shape(0.3).phaser(0.5).gain(0.6)
     .chunk(4, x => x.hpf(800))

// S3b
$: stack(
     s("bd*4").bank("RolandTR909").gain(0.9),
     s("~ hh").gain(0.5).pan(rand),
     note("c2").s("sine").lpf(200).ply(2)
   ).cpm(122 / 4)
$: note("c3 eb3 g3").sidechain(0.8).compressor("-20:20:10:.002:.02").crush(8).coarse(2).vowel("a")

// S3c
$: s("rim").off(1/8, x => x.add(note(12)).gain(0.4))
     .jux(rev).every(4, x => x.linger(0.25))
     .whenmod(8, 6, x => x.delayfeedback(0.85))
     .superimpose(x => x.late(0.02).hcutoff(2000))
     .arp("updown").segment(8).nudge(0.01).orbit(3)
```

### Tally

**Symbols: 61 distinct functions/signals used. 59 exist (96.7%). 2 do not.**

| | count |
|---|---|
| used | 61 |
| callable in `@strudel/web@1.3.0` | **59** |
| present in `doc.json` | 58 (`nudge` is callable but undocumented) |
| **misses** | **`sidechain`, `whenmod`** |

**Execution: 10 statements. 8 evaluated and queried clean; 2 threw.** The two failures are exactly the two symbol misses — no other statement produced an error, and all eight produced sensible hap counts (12, 64, 80, 50, 8, 16, 8, 16 haps over four cycles):

```
EVAL-FAIL: note(...).sidechain is not a function                       [S3b stmt 2]
EVAL-FAIL: s(...).off(...).jux(...).every(...).whenmod is not a function [S3c stmt 1]
```

**Read plainly: the model's Strudel is good.** Mini-notation (`"bd*2, ~ cp"`, `"<c3 eb3 g3 bb3>"`, `"~ x ~ x"`, `"[~ c2]"`), the chaining discipline, control names, signals (`sine`, `perlin`, `rand`), function-argument transforms (`x => ...`), `stack`, `$:` — all correct. The baseline is not "does it know Strudel"; it is **"which 3% is wrong, and does it know that it is wrong"** — and the answer to the second half is no.

### Argument shapes

Checked against `doc.json` params and against source. All arities used were valid. Two notes:

- `.swingBy(1/3, 8)` is **correct**: `export const swingBy = register('swingBy', (swing, n, pat) => ...)` ([`packages/core/pattern.mjs#L2358`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/packages/core/pattern.mjs#L2358)). Note that `doc.json`'s own `@param` names for it read `(subdivision, offset)`, which is **wrong/misleading metadata in the primary source**. Any remedy built on `doc.json` inherits this class of small inaccuracy.
- Several entries have **empty `params`** in `doc.json` despite taking arguments — `chunk`, `ply`, `arp`, `compressor`, `cpm`, `cutoff`. A signatures-only remedy is therefore weaker than it looks for exactly those; descriptions and examples carry the arity instead.

## 2. Failure modes — named, with evidence

**(a) TidalCycles carry-over. Confirmed.** `whenmod` is a real TidalCycles function and **does not exist anywhere in Strudel**: `grep -rn "whenmod" packages/` at `@8f81463` returns **zero hits**, and `typeof Pattern.prototype.whenmod === 'undefined'` in the published bundle. This is the predicted failure mode and it fired unprompted.

No Haskell-isms appeared in the generated code — no `d1 $`, no `#`, no `$` operator, no `|+|`. Strudel's own [`learn/strudel-vs-tidal.mdx`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/website/src/pages/learn/strudel-vs-tidal.mdx) documents precisely these deltas (`$` does not exist; `#` becomes a chained call; `||+` becomes `add.squeeze`; `foo x $ bar x` becomes `bar(x).foo(x)`). The risk is real but it manifests as **function-level** carry-over (`whenmod`), not syntax-level.

**(b) Plausible-but-nonexistent function. Confirmed.** `.sidechain(0.8)` does not exist. What *does* exist is a family named differently: `duckorbit` (synonym `duck`), `duckattack`, `duckdepth`, `duckonset` — documented at [`packages/core/controls.mjs#L1038`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/packages/core/controls.mjs#L1038) with the description *"Modulate the amplitude of an orbit to create a 'sidechain' like effect."* **This is the get-me-unstuck scenario failing in miniature**: the model reached for the right musical idea, named it in the vocabulary the idea is usually named in, and missed the library's actual name for it. No amount of "be careful" fixes that; only a reference that maps concept → name does.

**(c) Synonym collisions — silent, semantic, invisible to any error.** `size` is a registered synonym of `roomsize`, and `legato` is a registered synonym of `clip`. So in S3, `.roomsize(6).size(6)` sets one control twice; in S2b, `.legato(0.6).clip(0.8)` sets one control twice and the second wins. **Both evaluated clean and queried clean.** A verification loop cannot catch this class. `doc.json` carries `synonyms_text`, so a reference can.

**(d) Outdated / wrong-version APIs — the sleeper.** Comparing the 724 documented names (incl. synonyms) at `main` against the 1471-name callable union of npm 1.3.0: **116 documented names (16%) are not callable in the version the POC would ship.** Most are packages `@strudel/web` does not bundle (midi, motion, csound, draw), but the list also includes plain pattern functions — `all`, `each`, `flux`/`fluxBy`, `ftranspose`/`ftrans`, `juxFlip`, `setcpm`, and `duckorbit` itself (callable as a *method* but not as an export). Conversely ~half of the 1471 callable names are undocumented. **Any remedy sourced from `main`'s docs will confidently offer functions the POC's runtime does not have.** The fix is mechanical and is baked into the recommendation below: intersect the doc set with the *actual loaded bundle's* callable union.

## 3. Remedies, cheapest first — with measured cost

Token figures are **chars ÷ 4** (stated estimate; no tokenizer was available offline and no API key is present in this environment). Treat as ±15%.

| # | Remedy | Size | ~Tokens | Verdict |
|---|---|---|---|---|
| (a) | Hand-written cheatsheet | author's choice | ~500–1,500 | **Cheapest, but cannot clear scenario 3** — see below |
| (b0) | `doc.json` pasted verbatim | 880,961 ch | **~220,000** | Impossible: exceeds the context window |
| (b1) | Reformatted: name + syn + description + params + **all** examples | 147,740 ch | **~36,900** | Affordable but wasteful |
| (b2) | …max 1 example each | 137,898 ch | ~34,500 | |
| (b3) | …no examples | 110,845 ch | ~27,700 | |
| (b4) | **Signature index + 1-line description, filtered to what the shipped bundle can actually call (514 entries)** | 40,064 ch | **~10,000** | **Recommended** |
| (b5) | Signatures + synonyms only, same filter | 9,780 ch | **~2,450** | Viable floor |
| (b5)+ | b5 + `learn/strudel-vs-tidal.mdx` verbatim (4,562 ch) | 14,342 ch | **~3,600** | |
| (c) | Docs-lookup tool over `doc.json` | ~0 prompt tokens | +1 round trip per lookup, per turn | Buys nothing b4 doesn't already give |
| (d) | Retrieval over the docs | infra | — | Rejected by the map |

### Why (a) loses despite being cheapest

A hand-written cheatsheet is bounded by the vocabulary of whoever writes it. Scenario 3 is *"reaches for Strudel functions the human doesn't know"* — the cheatsheet author is the human. It would have contained `room`, `delay`, `lpf`; it would not have contained `duckorbit`, because the author would have written `sidechain` too. It also goes stale silently against a fast-moving library and encodes no version truth. It is cheaper in tokens and **more** expensive in the only currency that matters here.

### Why (b4) and not (c)

The docs-lookup tool costs ~0 prompt tokens, but: it adds a tool to the surface (which, per [02](02-anthropic-agent-loop-options.md), **invalidates the prompt cache** when added or removed mid-session), it adds a latency round-trip inside every turn that needs it, and — decisively — **the model does not know it needs to look up `sidechain`.** It was confident. A lookup tool is only reached for when the model suspects ignorance; the observed failures are exactly the cases where it does not. Pre-loading is the only remedy that fires without the model electing to use it.

At ~10k tokens (b4) this is ~5% of a 200k window, written once at the top of the system prompt, **fully prompt-cacheable** (static across the whole session — unlike the transcript), and it disappears from marginal cost after the first turn. That is not speculative infrastructure; it is a build step and a string.

### The build step, precisely

Three commands, run once per Strudel version bump, ~30 s:

1. `npm run jsdoc-json` in a checkout **pinned to the same version the app loads** → `doc.json`.
2. Import the app's own `@strudel/web` bundle, take `new Set([...Object.keys(module), ...Object.getOwnPropertyNames(Pattern.prototype)])` → the 1471-name callable union.
3. Emit `name(params) [=synonyms] — first sentence of description` for every `doc.json` entry whose name is in the union. **514 entries, 40 KB, ~10k tokens.**

Step 2 is what makes this correct rather than merely cheap: it is the only thing standing between the agent and the 116 documented-but-uncallable names.

Append `learn/strudel-vs-tidal.mdx` verbatim (+1,140 tokens) for the Tidal delta, and a short **do-not-use** list seeded from observed misses (`sidechain` → `duckorbit`/`duck` + `duckattack`/`duckdepth`; `whenmod` → Tidal-only, use `every`/`while`). Total **~11,200 tokens.**

## 4. Verification loop — necessary, not sufficient, and cheaper than 01 implies

**Does an evaluate-and-read-the-error loop replace pre-loading? No.** Of the four failure modes, a loop catches only (a) and (b) — the two that throw. It cannot catch (c) synonym collisions (evaluated clean, queried clean, silently wrong) and it cannot catch (d) version skew in the *other* direction (the model simply never reaches for a function it doesn't know exists). And a loop is a *correction* mechanism: it turns a confident wrong answer into a second attempt, costing a full round trip and, in a live performance, a visibly wrong bar. Pre-loading prevents; the loop recovers. **Both, with pre-loading first.**

**But the loop is cheap for the class of error the baseline actually produced.** [01](01-strudel-programmatic-surface.md) records that evaluation errors are "swallowed"; refining that from source **[both]** — `repl.evaluate` catches, and **does not rethrow and returns `undefined`**, but it *does* record the error in two host-reachable places ([`packages/core/repl.mjs#L438-L444`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/packages/core/repl.mjs#L438)):

```js
} catch (err) {
  logger(`[eval] error: ${err.message}`, 'error');
  console.error(err);
  updateState({ evalError: err, pending: false });
  onEvalError?.(err);
}
```

`state.evalError` is set (and `state.error = state.evalError || state.schedulerError`, [`repl.mjs#L53`](https://codeberg.org/uzu/strudel/src/commit/8f81463b9cb5ddd5f117ed7baef6a1fde9445dc2/packages/core/repl.mjs#L53)), and the `onEvalError` callback passed into `repl({...})` fires. So for **evaluation-time** errors — which is *every* failure the baseline produced — the host wrapper is a callback and a flag, not real work. The genuinely expensive half of 01's finding stands unchanged: **playback-time errors never reach `repl.state`** (`schedulerError` is dead code) and arrive only as an untyped `strudel.log` DOM event.

### Implication handed to ticket 05 (tool surface)

**Not a new tool. One required field on the apply tool.**

The tool that writes/evaluates Strudel must return, *synchronously in its `tool_result`*, the outcome of the evaluation:

- `{ ok: true, activeCode }` — taken from `repl.state.activeCode` after `evaluate` resolves; or
- `{ ok: false, error: <err.message> }` — captured from the `onEvalError` callback (or read off `repl.state.evalError`) during that call.

Two constraints on 05 fall out of it:

1. **`repl.evaluate` resolving is not success.** It resolves `undefined` on failure. The tool implementation must correlate the `onEvalError` firing with the in-flight call; it cannot infer success from the promise.
2. **Playback errors cannot be in that `tool_result`** — they happen after the turn ends. They need a separate path (the `strudel.log` listener from 01) and can only reach the agent on a *later* turn, which means 05 must decide whether the agent is told about them at all, and if so, how they get injected. Flag: this is the one place where "the agent acts only when instructed" (map, Out of scope) rubs against error reporting.

## RECOMMENDATION

**Remedy (b4): a generated, runtime-filtered signature index with one-line descriptions, ~10,000 tokens, pasted into the system prompt and prompt-cached. Plus `strudel-vs-tidal.mdx` verbatim (~1,140) and a short do-not-use list. Total ~11,200 tokens, built by a ~30-second, ~30-line build step.** No lookup tool, no retrieval.

Because:

- **The baseline is 59/61 (97%) on names and 8/10 statements evaluating clean.** The model does not need to be taught Strudel. It needs a *name authority* for the 3% and a *concept→name map* for discovery.
- **The one scenario-3 failure (`sidechain` → `duckorbit`) is a naming-discovery failure**, which is exactly and only what a name+description index fixes. Signatures alone (b5, ~2,450 tok) would list `duckorbit(orbit)` without telling the model it *is* sidechaining — the 7,500-token delta to (b4) buys precisely the thing the scenario needs.
- **A hand-written cheatsheet is bounded by the human's vocabulary**, which is the thing scenario 3 exists to exceed.
- **A lookup tool is unreached**, because the model was confident, not uncertain; and per 02 it perturbs the prompt cache.
- **Filtering against the loaded bundle's callable union is non-negotiable**: 116 of 724 documented names (16%) are not callable in npm 1.3.0.

Secondary: **keep the verification loop anyway**, cheaply, as an `ok/error` field on ticket 05's apply tool — it catches the residual and it is nearly free for evaluation-time errors.

## Follow-ups

- **To ticket 05 (tool surface):** the apply tool returns `{ok, activeCode | error}`; `repl.evaluate` resolving ≠ success; playback errors are out-of-band and need a separate decision.
- **New ticket candidate — "reference build step":** pin a Strudel version, generate `doc.json` from that exact tag, intersect with the loaded bundle's callable union, emit the index. Small, but it is a real build artifact with a staleness contract, and it is the hinge of this recommendation. Should also carry the do-not-use list as a growing file seeded from observed misses.
- **To the fog:** synonym collisions (`size`/`roomsize`, `legato`/`clip`) are silent semantic errors that neither the index nor the error loop catches — they evaluate clean. If they turn out to bite in practice, the remedy is a lint pass over agent-written code (detect two synonyms of one control in one chain), not more context.
- **Noted, not acted on:** `doc.json`'s `@param` metadata is unreliable (`swingBy` params are misnamed at source; `chunk`/`ply`/`arp`/`compressor`/`cpm`/`cutoff` have empty `params` despite taking arguments). This is why (b4) carries descriptions rather than trusting signatures.
